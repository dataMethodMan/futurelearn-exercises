        Region

        A region is a geographic area that contains separate availability zones in this model. Location choice can affect user proximity and data-location needs; confirm the relevant service options and requirements. Area A and Area D are different regions here.

        Availability zone

        An availability zone is a separated group of one or more data centres within a region. Multiple zones offer different physical fault boundaries. Applications and data need an appropriate design and service configuration to use that separation; they do not move automatically just because zones exist.

        Edge location

        An edge location can bring suitable content delivery closer to users. Cached content may be served there, while a cache miss or a dynamic request may still need the origin. It is not another full region or a universal copy of the customer's database.

        Explain availability

        Running an appropriately designed application and its data across separated zones can reduce the risk that one local incident stops the whole service. The benefit depends on the chosen service, replication, available capacity and how traffic and recovery are configured; we should test that arrangement rather than promise no downtime.

        Follow-up: How is this workload deployed today, and what interruption could the business tolerate while recovery takes place?

        Explain global performance

        Serving suitable content through an edge location can reduce the distance a user's request needs to travel for a cached response. The application's regional location and its origin still matter, especially for requests that cannot be served from the cache. We should measure the important user journeys before choosing an approach.

        Follow-up: Where are the users we need to serve, and which requests are slow or need to reach the application origin?

        Explain data recovery

        The answer depends on the storage service and the options in use. Suitable replication can keep another copy available when one location fails; backups support restoring earlier data when needed. We should confirm where the copies and backups are held and test that usable data can be recovered within the business's needs. Cloud placement alone is not a complete security or recovery plan.

        Follow-up: Which data and services are involved, what recovery time and possible data loss are acceptable, and when was restoration last tested?
