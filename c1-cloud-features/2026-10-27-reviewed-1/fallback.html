Cloud features in action - complete text version

Customers rarely ask for “elasticity” or “uptime”. They describe a business situation, and part of your job is to recognise which cloud feature answers it. In this activity you will read four short business scenarios, decide which core cloud features stand out in each, point to the sentence that shows each feature, and then match four customer needs to the feature that best meets them.

For each scenario, first choose the features that stand out. Then find the sentence in the scenario that shows each feature you chose. If a choice is not right, the feedback explains why and you can try again. The scenarios are short, so choose only what the text supports. Finally, match the customer needs to cloud features.

The businesses are fictional. This activity is not scored, and nothing you choose or write is stored or sent anywhere unless you save a text file yourself. Allow about 15 minutes.

How to use this version

You can do every stage on paper or in a document. Read each scenario, choose the features you think stand out, then find the sentence that shows each one. Read the feedback for every option and compare it with your choices. If you chose differently, work out why before moving on. At the end, match each customer need to a feature.

The six core features

Six core cloud features, and what each one means. Keep these in mind as you read.

Elasticity: Computing power can be added or removed as demand changes, helping a service handle sudden spikes and then reduce resources afterwards.

Scalability: Storage and processing capacity can be increased to handle more demand, such as business growth over time.

Pay-as-you-go pricing: Charges are based on the resources you use, so costs can track usage more closely than buying fixed infrastructure upfront.

Uptime: Uptime is the proportion of time a service is available. Resilient design can help keep a service available when a component fails.

Global access: Customers and teams can access services from different locations and regions, where that service is provided.

Resource pooling: Shared resources are used across many customers so capacity can be allocated efficiently.
