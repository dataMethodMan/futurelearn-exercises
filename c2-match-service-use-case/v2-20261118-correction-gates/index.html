        Five service capability cards

        Virtual-machine compute with configured scaling

        Run application software on virtual servers instead of owning physical hardware. Configure scaling policies to adjust capacity. The team still manages the operating system and application; scaling behavior and capacity limits need planning.

        Object storage

        Store and retrieve files as objects, such as videos and images. Choose storage class, access controls, retention and delivery arrangements for the workload. Storage alone is not a complete global content-delivery design or a guarantee of the lowest total cost.

        Managed relational database

        Use a compatible relational engine, such as MySQL, while the service handles selected routine administration. Confirm backup, maintenance and availability options; the team remains responsible for data, access, data structures and application design.

        Event-driven functions

        Run configured code when an event occurs, such as a file upload. This can suit short, intermittent processing without managing a continuously running application server for that task. Triggers, permissions, runtime limits, retries and error handling still need configuration.

        Managed key-value database

        Store and retrieve data through a key-based access model using a managed database. It can suit simple access patterns with variable demand. Validate how demand is distributed across keys, capacity settings and end-to-end performance against the actual workload.
